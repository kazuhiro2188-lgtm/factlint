# factlint

**AIが書いた文章の数値に、根拠があるかを機械的に確かめる。検証にAIを使わない。**

## 何を解決するのか

生成AIに数値データを渡して文章を書かせると、**入力に存在しない数字**が混ざることがあります。

```
入力: { "assets": 152800, "liabilities": 167400 }

出力: 「資産は $152,800、負債は $167,400。充足率は 91.3% で、前月比 12% 改善しました」
                                                            ~~~~~~~~~
                                            前月のデータは渡していない。この数字に根拠はない
```

文章の言い回しの誤りは、読めば気づきます。**もっともらしい数字には気づけません。** そしてその数字は、そのまま経営判断や外部への報告に使われます。

factlint は、出力に現れた数値ひとつひとつについて「ソースから辿れるか」を判定します。

```console
$ factlint --source data.json --output report.md

  ✓ exact       $152,800       3:5  assets(152800) = 152800
  ✓ exact       $167,400       3:18  liabilities(167400) = 167400
  ✓ derived     91.3%          3:34  assets(152800) ÷ liabilities(167400) × 100 = 91.2784
  ✓ derived     2 件            4:12  要素数(positions) = 2
  ✓ derived     110,100        4:25  合計(principal 横断: 2件) = 110100
  ✗ ungrounded  12%            7:7
      最も近い候補: collected(2133) ÷ collected(198) = 10.7727  (差 1.22727)

  10件中 9件に根拠あり (90.0%)  exact 4 / derived 5
  根拠なし 1件

$ echo $?
1
```

## なぜAIで検証しないのか

幻覚検出の一般的な手法は「別のAIに検証させる」（LLM-as-a-judge）です。実装は簡単で、対象範囲も広い。しかし**出荷前のゲート**として使おうとすると壁に当たります。

| 問題 | 内容 |
|---|---|
| 同じ入力で結果が変わる | CIの合否判定は再現性がなければ成立しない |
| 遅い・課金される | 出荷のたびに毎回通すには重い。結果「重要なときだけ」になる |
| **検証者を検証できない** | 検証側のAIが誤判定しても、それを検出する外側の仕組みが無い |

3つ目が決定的です。**検証する仕組み自体が検証不能なら、それはゲートではありません。**

factlint は対象を「数値の根拠が辿れるか」に限定し、決定論的に判定します。範囲を狭める代わりに、結果は毎回同じで、速く、無料で、判定ロジック自体をテストできます。

→ 詳細: [ADR-0001: 検証経路にAIを入れない](docs/adr/0001-verification-path-contains-no-ai.md)

## 判定の3種類

| 判定 | 意味 |
|---|---|
| `exact` | ソースにその値がそのまま存在する |
| `derived` | ソースの値から計算で導ける（合計・平均・差分・比率など） |
| `ungrounded` | どちらでもない。根拠を辿れない |

### `derived`（派生値）が本質

素朴な実装は「出力の数値がソースに含まれるか」だけを見ます。これは動きますが、**実務では3日で使われなくなります。**

```
ソース: [1200, 3400, 800]
出力:   「合計 5,400 件。平均は 1,800 件、最大は 3,400 件でした」
```

`5400` も `1800` もソースにありません。しかし正しい文章です。派生値を許可しないツールは誤検知だらけになり、やがて回避されます。**回避されたゲートは、無いのと同じです。**

対応する演算:

| 種別 | 演算 |
|---|---|
| 2値 | `a + b` / `a - b` / `a ÷ b` / `a ÷ b × 100` / `(a - b) ÷ b × 100` |
| 集約 | 合計 / 平均 / 最大 / 最小 / 配列の要素数（全体・グループごと・同じ項目名の横断） |

ただし**無関係な2値は掛け合わせません**。「あるポジションの元本 ÷ 全体の負債」のような意味をなさない計算が偶然一致してしまうためです（実際に初回のドッグフーディングで発生しました）。同じまとまりの中の値どうし、または同じ項目名の値どうしに限定しています。

→ 詳細: [ADR-0002: 派生値を一級市民として扱う](docs/adr/0002-derived-values-are-first-class.md)

### 丸めの扱い

AIは数値を丸めて書きます。`91.2817...%` を `91.3%` と書くのは正しい。

- 通常: **書かれた小数桁数に合わせて**候補を丸めて照合する
- `約` `およそ` `about` を伴う場合: **有効桁数**に合わせる（`約1,800` は `1833` に一致する）

### 既定で数値として扱わないもの

誤検知は「使われなくなる」に直結するため、以下は既定で除外します（設定で有効化できます）。

西暦（1900〜2100の裸の4桁整数） / 日付・時刻表記 / バージョン番号 / 箇条書きの番号

## 使い方

### CLI

```bash
npm install -D factlint

npx factlint --source data.json --output report.md
```

| オプション | 内容 |
|---|---|
| `--source, -s` | 入力データ。JSON でも素のテキストでもよい。`-` で標準入力 |
| `--output, -o` | 検証するAI生成文。`-` で標準入力 |
| `--format, -f` | `human`（既定） / `json` / `github` |
| `--max-pairwise <n>` | 2値演算を行うソース値の上限（既定 80） |
| `--allow-ungrounded <n>` | 根拠なしを何件まで許すか（既定 0） |

終了コード: `0` = 許容件数以内 / `1` = 超過 / `2` = 引数やファイルの誤り

### ライブラリ

```ts
import { check } from "@factlint/core";

const report = check({
  source: { assets: 152800, liabilities: 167400 },
  output: "充足率は 91.3% です。前月比 12% 改善しました。",
});

report.stats.ungrounded; // 1
report.results[1].nearest; // { expression: "...", value: 9.55, delta: 2.27 }
```

`@factlint/core` は**実行時依存がゼロ**です。Node でもブラウザでも、バンドラを通さずそのまま `import` できます（[デモページ](apps/demo/index.html)は実際にそうしています）。

### CI に組み込む

```yaml
- name: AI生成レポートの数値を検証
  run: npx factlint -s data.json -o report.md --format github
```

`--format github` を指定すると、根拠のない数値がプルリクエストの差分に直接注釈として付きます。

## やらないこと

意図的に対象外としています。範囲を広げると、どれも中途半端になるためです。

| やらないこと | 理由 |
|---|---|
| 文章表現の正しさの検証 | 決定論的に解けない。LLM-as-a-judge の領域 |
| 固有名詞・引用の検証 | 表記ゆれの正規化が別問題として大きい |
| AIの呼び出し | 一切使わない。それが存在意義 |

### 既知の限界

- **偽陰性（見逃し）がありうる**。候補の組み合わせが増えるほど、偶然一致する数値が出ます。誤検知でツールが捨てられるより見逃しのほうがましだ、という判断です（ADR-0002）
- ソース値が上限を超えると2値演算を打ち切ります。この場合は結果に明示します（黙って精度を落としません）
- 「1行目」「第3章」のような序数は、単位のない数値として検出対象になります
