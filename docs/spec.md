# factlint 仕様書

> 何を作るか・なぜ作るかを定める。技術スタックはここには書かない（→ `docs/adr/`）。

## 1. 解決する問題

生成AIに数値データを渡して文章を書かせると、**入力に存在しない数字**が混ざることがある。

```
入力: { "資産": 152800, "負債": 167400 }
出力: 「資産は $152,800、負債は $167,400。充足率は 91.3% で、前月比 12% 改善しました」
                                                              ~~~~~~~~~~~~~~~
                                                              入力に無い。前月のデータは渡していない
```

文章の言い回しの誤りは読めば気づく。**もっともらしい数字は気づけない。** そして数字は、そのまま経営判断や外部への報告に使われる。

### 1.1 なぜ既存の方法では足りないか

幻覚検出の一般的な手法は「別のAIに検証させる」（LLM-as-a-judge）である。これには運用上の問題がある。

| 問題 | 内容 |
|---|---|
| 非決定的 | 同じ入力で結果が変わる。CIの合否判定に使えない |
| 遅い | 1回あたり数秒〜数十秒。出荷前チェックに毎回挟めない |
| 課金 | 検証のたびにAPI費用が発生する |
| 検証者も幻覚する | 検証する側のAIが誤判定した場合、それを検出する手段がない |

**数値の照合は、AIを使わずに決定論的に解ける。** 本ツールはそこだけを、確実に解く。

## 2. 何を作るか

入力（ソースデータ）と出力（AI生成文）を受け取り、**出力に現れる数値のうち、ソースから根拠が辿れないもの**を報告する。

### 2.1 3つの判定

| 判定 | 意味 | 例（ソース: 資産152800 / 負債167400） |
|---|---|---|
| **exact** | ソースにその値が存在する | `$152,800` |
| **derived** | ソースの値から計算で導ける | `91.3%` ← 152800 ÷ 167400 × 100 |
| **ungrounded** | どちらでもない | `12%` |

### 2.2 「derived（派生値）」が本質

単純な文字列照合では実用にならない。AIは与えられた数値をそのまま書くだけでなく、**合計・差分・比率を計算して書く**からである。

```
ソース: [1200, 3400, 800]
出力:   「合計 5,400 件、平均 1,800 件、最大は 3,400 件」
        すべて正当。しかしソースに 5400 も 1800 も存在しない
```

派生値を許可しないツールは誤検知だらけになり、3日で使われなくなる。**派生値を追跡できて初めて、実務のチェックに組み込める。**

対応する演算:

| 種別 | 演算 |
|---|---|
| 2値 | `a + b` / `a - b` / `a ÷ b` / `a ÷ b × 100` / `(a - b) ÷ b × 100` |
| 集約 | 合計 / 平均 / 最大 / 最小 / 件数（全体、および同じ階層のグループごと） |

### 2.3 丸めの扱い

AIは数値を丸めて書く。`91.28...%` を `91.3%` と書くのは正しい。

- 通常: **出力に書かれた小数桁数に合わせて**候補を丸め、一致するかを見る
- `約` `およそ` `about` `~` を伴う場合: **有効数字**に合わせて丸める（`約1,800` は `1833` に一致する）

### 2.4 除外するもの（既定）

誤検知は「使われなくなる」に直結するため、以下は既定で数値として扱わない。

| 対象 | 理由 |
|---|---|
| 西暦（1900〜2100 の裸の4桁整数） | 「2026年」は根拠を要求する数値ではない |
| 日付表記（`2026-09-08` `2026/09/08` `9月8日`） | 同上 |
| バージョン番号（`v1.2.3`） | 同上 |
| 箇条書きの番号（行頭の `1.` `2.`） | 同上 |

すべて設定で有効化できる。

### 2.5 根拠なしの場合、最も近い候補を示す

`ungrounded` と判定して終わりにしない。**最も近い派生値を差分つきで併記する。**

```
✗ 12%  根拠なし
   最も近い候補: (152800 - 167400) ÷ 167400 × 100 = -8.72  （差 20.72）
```

これは「本当に幻覚なのか、計算の元データが足りないだけなのか」を人が1秒で判断するためにある。前者ならプロンプトの問題、後者は入力の問題であり、打つ手がまったく違う。

## 3. 提供形態

| 形態 | 用途 |
|---|---|
| ライブラリ | アプリに組み込み、AI出力を返す前に検証する |
| CLI | CI（自動テスト）に組み込む。根拠なしが1件でもあれば終了コード 1 |
| Web | 貼り付けてその場で確認する。導入前の評価用 |

## 4. やらないこと

意図的に対象外とする。範囲を広げると、どれも中途半端になるため。

| やらないこと | 理由 |
|---|---|
| 文章表現の正しさの検証 | 決定論的に解けない。LLM-as-a-judge の領域 |
| 固有名詞・引用の検証 | 表記ゆれの正規化が別問題として大きい（将来の検討対象） |
| 数値以外の推論の検証 | 同上 |
| AIの呼び出し | 本ツールは一切AIを使わない。それが存在意義 |

## 5. 完成の定義

- [ ] ソース（JSON / テキスト）と出力文から、exact / derived / ungrounded を判定できる
- [ ] 派生値（2値演算・集約）を追跡できる
- [ ] 丸め・概数を正しく扱える
- [ ] 誤検知の既定除外が効いている
- [ ] 根拠なしに対し最も近い候補を提示できる
- [ ] ライブラリ / CLI / Web の3形態で同じ結果になる
- [ ] エンジンの実行時依存がゼロである
- [ ] CI でテスト・型チェック・ビルドが通っている
