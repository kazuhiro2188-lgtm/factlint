# ADR-0002: 派生値を一級市民として扱う

- 状態: 採用
- 日付: 2026-09-08

## 背景

素朴な実装は「出力に現れた数値が、ソースの数値集合に含まれるか」を見る。これは動くが、実務では**3日で使われなくなる**。

AIは与えられた数値をそのまま書くだけではない。**計算して書く。**

```
ソース: [1200, 3400, 800]
出力:   「合計 5,400 件。平均は 1,800 件、最大は 3,400 件でした」
```

`5400` も `1800` もソースに存在しない。素朴な実装はこれを幻覚として報告する。しかし正しい文章である。

誤検知が続くツールは信用されなくなり、やがて `--no-verify` を付けて回避されるようになる。**回避されたゲートは、無いのと同じである。** むしろ「ゲートを通した」という誤った安心を与える分だけ有害になる。

## 決定

**派生値（ソースの値から計算で導ける値）を、根拠ありとして扱う。** 対応する演算を明示的に定義し、どの演算でその値に到達したかを説明として提示する。

| 種別 | 演算 |
|---|---|
| 2値 | `a + b` / `a - b` / `a ÷ b` / `a ÷ b × 100` / `(a - b) ÷ b × 100` |
| 集約 | 合計 / 平均 / 最大 / 最小 / 件数（全体、および同じ階層のグループごと） |

判定結果には必ず**到達経路**を付ける。`91.3%` を通したなら「152800 ÷ 167400 × 100 = 91.28」と書く。通した理由が読めなければ、利用者はツールを信用できない。

## 結果

### 得るもの

- 実務の文章をそのまま通せる。誤検知で回避されない
- 「なぜ通ったか」が説明として残る。レビューで追える

### 失うもの・引き受けるリスク

- **偽陰性（見逃し）が増える**。候補となる値の組み合わせが増えるほど、偶然一致してしまう数値が出る。特にソースの数値が多い場合に起きやすい
- 計算量が増える。2値演算は候補数の2乗に比例する

見逃しのリスクは意図的に引き受ける。**誤検知でツールが捨てられるほうが、見逃しより損失が大きい**と判断した。ゲートは、使われ続けて初めて価値を持つ。

計算量は上限で抑える。ソース値が既定の上限を超えた場合は2値演算を打ち切り、集約のみで判定する。この場合は結果にその旨を明示する（黙って精度を落とさない）。

## 却下した案

| 案 | 却下理由 |
|---|---|
| 任意の四則演算を深さ2〜3まで全探索する | 偶然一致が急増し、根拠なしをほぼ検出できなくなる。ゲートとして機能しない |
| 派生値を扱わず、利用者に許可リストを書かせる | 出力のたびに数値が変わるため、許可リストが保守不能になる |
| ソースにAIが計算過程を書かせて、それを照合する | AIの自己申告を信じることになり、ADR-0001 の判断と矛盾する |

## 追記（2026-09-08）: 実データで偽陽性が出たため、組み合わせを制限した

初回のドッグフーディング（自分の実データでの試用）で、想定していた偽陰性が**即座に**現れた。

```
ソース: assets 152800 / liabilities 167400
        positions[0] = { principal 90000, collected 198 }
        positions[1] = { principal 20100,  collected 2133 }

出力:   「前月比では 12% 改善しました」  ← 前月のデータは渡していない。根拠は無い

判定:   derived ✓  principal(20100) ÷ liabilities(167400) × 100 = 12.01
```

「あるポジションの元本を、全体の負債で割る」という**意味をなさない計算**がたまたま 12.01 になり、根拠のない主張を通してしまった。

### 追加の決定

2値演算を許す組み合わせを、次のどちらかに限定する。

- **同じグループに属する値どうし**（同じ行の 回収額 ÷ 元本）
- **同じラベル（項目名）を持つ値どうし**（各行の 元本 の合計）

この2つで、実務の文章に出てくる計算はほぼ覆える。一方、上記のような無意味な組み合わせは生成されなくなる。

あわせて、根拠の選び方を「最初に一致したもの」から「**最もぴったり合い、式が短いもの**」に変えた。説明として読める根拠が選ばれるようになる（`要素数(positions) = 2` が `件数(positions[0]) = 2` より先に選ばれる、など）。

この事故は `packages/core/tests/check.test.ts` に回帰テストとして残してある。
