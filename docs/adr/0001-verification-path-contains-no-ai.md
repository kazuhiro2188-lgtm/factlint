# ADR-0001: 検証経路にAIを入れない

- 状態: 採用
- 日付: 2026-09-08

## 背景

AI生成文の幻覚を検出する一般的な方法は、別のAIに検証させること（LLM-as-a-judge）である。実装は容易で、対象範囲も広い。

しかし、この方式を出荷前のゲート（合否を判定して通す・止める仕組み）として使おうとすると、次の壁に当たる。

1. **同じ入力で結果が変わる**。CIの合否判定は再現性がなければ成立しない。「昨日は通ったが今日は落ちた、コードは変えていない」が起きる
2. **遅い・課金される**。出荷のたびに毎回通すには重すぎる。結果として「重要なときだけ通す」運用になり、重要なときの判断が人によってぶれる
3. **検証者を検証できない**。検証側のAIが誤判定したとき、それを検出する外側の仕組みが存在しない。誤判定は静かに通過する

3 が決定的である。**検証する仕組み自体が検証不能なら、それはゲートではない。**

## 決定

**検証経路にAIを一切含めない。** 対象を「数値の根拠が辿れるか」に限定し、決定論的に判定する。

数値は、AIを使わずに照合できる。丸めも派生値も規則で書ける。範囲を狭める代わりに、結果は毎回同じで、速く、無料で、テストできる。

## 結果

### 得るもの

- 同じ入力なら必ず同じ結果。CIの合否判定に使える
- 実行時依存ゼロ・ミリ秒単位。出荷のたびに毎回通せる
- 判定ロジック自体をユニットテストで検証できる（＝検証者を検証できる）
- 検証のためにデータを外部へ送信しない。機密データを扱う現場でそのまま使える

### 失うもの

- 文章表現の誤り・固有名詞の誤り・論理の飛躍は検出できない
- 対象は数値のみ

この割り切りは意図的である。**広く浅く検出して信用できない結果を返すより、狭く確実に検出して合否判定に使えるほうが、運用上の価値が高い。** 文章表現の検証が必要なら、その用途にLLM-as-a-judgeを併用すればよい。両者は競合しない。

## 却下した案

| 案 | 却下理由 |
|---|---|
| LLMで検証し、結果をキャッシュして再現性を確保する | キャッシュが効くのは同一入力のときだけ。入力が1文字変われば再び非決定的になる |
| LLMを併用し、数値は決定論・文章はLLMで判定する | v1のスコープを超える。まず数値だけを確実に解く。併用は利用者が選べばよい |
| 埋め込みベクトルの類似度で根拠を照合する | 閾値の設定が経験則になり、「なぜこの判定になったか」を説明できない。ゲートには説明可能性が要る |
